# 행복-가게 개선 기획서

- 작성일: 2026-11-11
- 대상: Breaktime 앱의 행복-가게(`lib/happiness_shop_2/`)
- 근거: 2026-11-11 코드·디자인 검토, 배포된 파이어스토어 보안 규칙 조회 결과, 기존 문서(`docs/happiness_shop_*.md`, `docs/happiness_vitamin_feature_plan.md`)
- 일정·인력·예산은 자료에 없습니다. 단계 순서만 정하고 기간은 사람이 정합니다.

---

## 1. 개요

행복-가게는 사용자가 앱 활동으로 모은 **사랑하기**(하트, `users/{uid}.heartCount`)를 써서 글귀·운세·위로·꽃말·레시피·여행·음악 카드와 행복 비타민 슬롯을 받는 곳입니다.

지금은 8개 탭이 모두 열려 있지만, 서랍 메뉴 이름은 아직 "행복-가게(준비중)"입니다. 검토 결과, 기능을 더 늘리기 전에 **데이터 보안과 사랑하기 차감의 신뢰**를 먼저 바로잡아야 합니다.

이 기획서의 목표는 세 가지입니다.

1. 사용자 데이터와 사랑하기를 안전하게 지킵니다.
2. 사랑하기를 쓰는 과정을 이해하기 쉽고 믿을 수 있게 만듭니다.
3. 8개 탭의 화면 모양과 상태 표시를 하나의 규칙으로 맞춥니다.

## 2. 현황

### 2.1 카테고리별 상태

| 카테고리 | 상태 | 사용자가 할 수 있는 일 | 비용 | 저장 위치 | AI(Gemini) |
| --- | --- | --- | --- | --- | --- |
| 행복 비타민 | 구현(영상 업로드 고장) | 슬롯에 사진·영상·링크·글귀 담기, AI 글귀, 슬롯 구매 | 슬롯 1개에 5개, AI 글귀 무료 | `happiness_slots`, Storage `users/{uid}/happiness_*` | 사용 |
| 행복 글귀 | 구현 | 하루 1회 생각 쓰기 → AI 명언·위로 글, 기록 | 1개 | `users/{uid}/quotes`, `daily_quotes` | 사용 |
| 행복 운세 | 구현 | 기분 고르기 → AI 운세, 다시 받기, 기록 | 1개 | `users/{uid}/fortunes` | 사용 |
| 행복 위로 | 구현 | 10자 이상 입력 → AI 편지, 위기 단어면 고정 안내 | 1개 | `users/{uid}/comforts` | 사용 |
| 음악·꽃말·레시피·여행 | 일부 구현 | 글 카드 무작위 뽑기만 가능, 음악은 소리 없음 | 1개 | 읽기 `shop_catalog/{분류}/items`, 쓰기 `users/{uid}/{분류}_picks` | 미사용 |

- 서버에서 카드를 못 읽을 때 쓰는 앱 내장 카드는 레시피 1개, 꽃말 2개뿐입니다.
- `shop_catalog`, `daily_quotes`에 실제 데이터가 있는지는 확인하지 못했습니다.

### 2.2 사랑하기를 얻고 쓰는 방법

| 구분 | 방법 | 수량 | 횟수 |
| --- | --- | --- | --- |
| 얻기 | 서랍 메뉴의 사랑하기 누르기 | 1개 | 하루 1회 |
| 얻기 | 행복-미션 100% 달성 | 1개 | 하루 1회 (2026-11-11 추가) |
| 얻기 | 행복-함 작성 | 1개 | 하루 1회 (2026-11-11 추가) |
| 쓰기 | 글귀·운세·위로·음악·꽃말·레시피·여행 | 1개 | 제한 없음 |
| 쓰기 | 비타민 슬롯 늘리기 | 5개 | 최대 20칸 |

하루에 최대 3개를 얻고, 카드 하나에 1개를 씁니다.

## 3. 먼저 해결할 문제

아래 세 가지는 새 기능보다 먼저 처리해야 합니다.

### 3.1 [가장 급함] 보안 규칙이 모두 열려 있습니다

- **배포된 규칙**(2026-11-11 조회): 모든 문서에 `allow read, write: if true`입니다. 로그인하지 않은 사람도 모든 사용자의 행복-함 일기(비공개 글 포함), 할 일, 사랑하기 수를 읽고 바꾸고 지울 수 있습니다.
- **저장소의 `firestore.rules`**(2025-06 수정): 행복-가게 경로(`quotes`, `fortunes`, `comforts`, `*_picks`, `happiness_slots`, `shop_catalog`, `daily_quotes`)가 없어서 모두 거부됩니다. 이 파일을 그대로 배포하면 행복-가게가 멈추고, 사랑하기만 빠지고 결과는 저장되지 않습니다.
- **할 일**
  1. 행복-가게 경로를 넣은 새 규칙을 만듭니다.
  2. 사용자가 `heartCount`, `slotCount`, `maxSlots`, `heartRewards`를 마음대로 올리지 못하게 막습니다. 늘리는 쪽은 하루 보상 규칙에 맞을 때만 허용하거나, Cloud Functions(서버 함수)로 옮깁니다.
  3. 다른 사용자의 `users` 문서는 필요한 필드만 읽게 줄입니다. 지금 저장소 규칙은 로그인한 누구나 남의 문서 전체를 읽을 수 있습니다.
  4. 파이어베이스 에뮬레이터로 규칙을 시험한 뒤 배포합니다.
- **결정 필요:** 규칙 변경과 배포는 사람이 승인한 뒤에만 합니다.

### 3.2 사랑하기를 먼저 빼고, 실패해도 돌려주지 않습니다

- 운세·위로·글귀·카드 뽑기는 모두 "사랑하기 차감 → AI 호출·저장" 순서입니다. AI가 실패하면 기본 문장을 결과로 저장하므로, 사용자는 1개를 내고 일반 문장을 받습니다.
- 네트워크 오류도 "사랑하기가 부족해요"로 보입니다(`useHearts`가 모든 오류를 false로 돌려줍니다).
- **할 일:** 결과를 만든 뒤에 차감하거나, 실패하면 돌려줍니다. 기본 문장이 나가면 차감하지 않습니다. 오류는 "부족"과 "연결 문제"를 나눠 알려 줍니다.

### 3.3 결과가 'pending'에 멈출 수 있습니다

- 운세·위로는 AI 생성을 기다리지 않고 진행해서, 그 사이 앱이 꺼지면 결과가 영구히 'pending'으로 남습니다. 복구하는 코드가 없습니다.
- **할 일:** 'pending' 결과는 다시 열 때 이어서 만들거나, "다시 만들기" 버튼(무료)을 보여 줍니다.

## 5. 화면 구성과 동작

### 5.1 행복-가게 첫 화면

| 영역 | 내용 | 동작 |
| --- | --- | --- |
| 잔액 칩 | ❤ 사랑하기 N | 누르면 "얻는 방법" 안내 시트를 엽니다. |
| 탭바 | 8개 분류(이모지 + 이름 한 줄) | 가로 스크롤입니다. 부제(10px)는 빼서 큰 글자에서도 넘치지 않게 합니다. |
| 탭 내용 | 분류별 화면 | 아래 공통 흐름을 따릅니다. |

### 5.2 공통 흐름(사랑하기를 쓰는 탭)

1. 사용자가 실행 버튼을 누릅니다. 버튼에는 비용이 적혀 있습니다(예: "운세 받기 · 사랑하기 1개").
2. 확인 창: "사랑하기 1개를 사용합니다. 남은 사랑하기 N개" → [취소] [사용하기]
3. 결과를 만드는 동안 진행 표시를 보여 줍니다.
4. 성공하면 결과 카드를 보여 주고 사랑하기를 1개 뺍니다.
5. 실패하면 "결과를 만들지 못했어요. 사랑하기는 빠지지 않았어요" + [다시 시도]를 보여 줍니다.
6. 잔액이 부족하면 2단계 대신 부족 안내(2-3)를 보여 줍니다.

### 5.3 상태 표시

| 상태 | 표시 |
| --- | --- |
| 로딩 | 탭 가운데 진행 표시 하나로 통일합니다. |
| 빈 상태 | 그림 + 한 줄 설명 + 첫 실행 버튼 |
| 오류 | "연결이 원활하지 않아요" + [다시 시도] (예외 원문 없음) |
| 부족 | 2-3 안내 + [행복-미션으로] [행복-함으로] |

## 6. 디자인 검토 결과

### 6.1 일관성

- 앱 테마(`app_theme.dart`)에 기본 색(#FF9E80), 글꼴(SUIT), 제목 스타일이 있지만, 행복-가게는 이를 거의 쓰지 않고 색과 크기를 직접 적었습니다. 행복-가게 안에서 앱 글꼴을 지정한 곳은 0곳입니다.
- 탭마다 배경 그라데이션 색이 다르고(주황·파랑·보라·분홍·초록), 운세·위로만 방향이 가로입니다.
- 제목 위치와 크기가 탭마다 다릅니다.
- **제안:** 제목·본문은 테마 글자 스타일, 배경·글자색은 테마 색을 씁니다. 탭별 색은 연한 강조색 하나로 줄입니다.

### 6.2 다크 모드

- 대부분 흰색·짙은 회색을 직접 나눠 씁니다.
- "오늘의 명언" 카드는 다크 모드에서도 갈색 글자를 써서 읽기 어려울 것으로 추정합니다.
- **제안:** 테마 색(surface/onSurface)으로 바꾸고, 명언 카드 글자색은 다크 모드용을 따로 정합니다.

### 6.3 작은 화면(360~375dp)과 큰 글자

- 위로·운세·카드 탭은 스크롤 없는 화면에 입력창과 목록이 함께 있어, 키보드가 올라오면 넘칠 가능성이 큽니다.
- 가게 헤더(로고·제목·잔액)는 줄어들 여지가 없어 큰 글자에서 넘칠 수 있습니다.
- 글귀 탭은 명언 카드, 작성 카드, 결과가 쌓여 결과 영역이 아주 좁아집니다. 빈 상태 로고가 300×300 고정입니다.
- **제안:** 탭 내용을 스크롤 가능한 구조로 바꾸고 키보드 높이를 반영합니다. 제목은 길면 말줄임 처리합니다. 고정 크기는 화면 폭 비율로 바꿉니다. 이 작업은 360dp·375dp·큰 글자(1.3배)에서 확인합니다.

### 6.4 접근성

- 기본 색 #FF9E80 위의 흰 글자, 흰 배경 위의 기본 색 글자는 대비가 약 2:1로 추정되어 권장 기준(4.5:1)에 못 미칩니다.
- 10px·11px 글자가 있습니다(탭 부제, 글귀 기록 작가 이름).
- 글귀 기록의 삭제 버튼은 누르는 영역이 약 20dp로, 권장 48dp보다 작습니다.
- 알약 버튼·아이콘 버튼에 화면 낭독용 이름이 없습니다.
- 위로 기록은 삭제할 때 확인 창이 없습니다.
- **제안:** 버튼 배경을 더 진한 색으로 바꾸거나 글자를 어둡게 합니다. 글자는 12px 이상, 누르는 영역은 48dp 이상으로 합니다. 버튼에 이름(tooltip·Semantics)을 붙이고, 삭제할 때는 확인 창을 띄웁니다.
