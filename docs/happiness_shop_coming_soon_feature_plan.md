## 2. 제품 목표

행복상점은 “하트로 작은 행복을 고르는 컬렉션”이다.  
미완성 6개 카테고리는 **짧은 입력 → 하트 1개 소비 → 즉시 보상(카드/음악/문장)** 루프를 공유하며, 비타민(기록)·글귀(AI 문장)와 함께 **감정 케어 루틴**을 완성한다.

### 2.1 공통 성공 기준

- 첫 CTA까지 3탭 이내
- 하트 소비 → 결과 표시까지 체감 5초 이내(AI는 pending UI)
- ko/en 동시 지원
- 결과 히스토리 재열람 가능
- Remote Config로 카테고리 on/off

---

## 3. 공통 UX / 경제 설계

### 3.1 하트 경제

| 액션 | 비용 | 비고 |
|------|------|------|
| 기본 받기/뽑기/생성 | 1하트 | `HeartCost.*` |
| 같은 날 재생성 | 1하트 | 확인 다이얼로그 |
| 히스토리 열람 | 0 | — |
| Music 미리듣기(선택) | 0 | 15초, 전체는 언락 |

하트 부족 시: “하트가 부족해요” + 미션/로그인 보너스 안내(기존 하트 획득 경로와 연결).

### 3.2 공통 화면 골격

```
[카테고리 아이콘 + 타이틀]
[오늘 결과 카드 또는 Empty]
[CTA: 하트 1로 ○○ 받기]
[히스토리 보기]
```

Coming soon 그라데이션·다크모드 패턴을 유지하되, Empty를 실기능으로 교체한다.

### 3.3 공통 상태

`idle → confirming_spend → pending → success | failed | insufficient_hearts`

### 4.1 행복 음악 (Music) 🎵

#### 컨셉
기분에 맞는 **짧은 행복 사운드/곡**을 듣고, 마음에 들면 하트로 언락해 컬렉션에 담는다.

#### 타깃 유저 행동
1. 무드 태그 선택(예: 고요, 설렘, 응원) 또는 “오늘의 추천”
2. 리스트/카드에서 미리듣기
3. 하트 1로 언락 → 전역 `MusicProvider`로 재생·루프

#### 핵심 기능
| 기능 | 설명 | MVP |
|------|------|-----|
| 카탈로그 브라우징 | Firestore `shop_catalog/music` | ✅ |
| 무드 필터 | tags 기반 | ✅ |
| 미리듣기 | 15초 또는 페이드 | ✅ |
| 하트 언락 | `music_unlocks` | ✅ |
| 재생 연동 | `MusicProvider` | ✅ |
| 좋아요/플레이리스트 | 사용자 즐겨찾기 | Phase 2 |
| 사용자 업로드 | Storage | Out of scope |

#### 화면
- 탭 메인: 추천 1장 + 리스트
- 언락된 곡: “내 행복송” 섹션
- 재생 바: 기존 메인 뮤직 UI와 충돌 없이 Provider 공유

#### 콘텐츠 운영
- Firebase Storage `music/` + 카탈로그 메타데이터 시드 20~50곡
- 저작권: 자체/라이선스 확인된 에셋만

#### KPI
언락 전환율, 언락 후 재생 완료율, DAU당 음악 탭 체류

### 4.2 행복 운세 (Fortune) 🍀

#### 컨셉
하루 한 번, **가벼운 행운 메시지**로 하루를 여는 리추얼. 점술 심화가 아니라 “오늘의 작은 응원”.

#### 타깃 유저 행동
1. (선택) 오늘 기분 칩 선택 — Todo/Relax와 연동 가능
2. “오늘의 운세 받기” (하트 1)
3. 운세 카드 확인 → 히스토리에 저장

#### 결과 카드 구성
| 영역 | 내용 |
|------|------|
| 한줄 운세 | 40자 이내 |
| 오늘의 키워드 | 1~3개 |
| 행운 팁 | 실천 가능한 한 줄 |
| 응원 문장 | 2~3줄 |

#### 규칙
- **유저당 날짜당 1회 기본 제공**, 재생성은 추가 하트
- 의료·재물·관계 단정 금지 — “가벼운 메타포” 톤 (프롬프트 가드레일)
- 미성년 고려: 공포/사주 심화 UI 금지

#### AI 입력
`date`, `locale`, `mood?`, (선택) `nickname`

#### MVP / Phase
| | |
|--|--|
| MVP | 기분 칩 + AI 카드 + 히스토리 + 일 1회 |
| Phase 2 | 주간 운세 모음, 공유 이미지 |
| Out | 유료 사주, 외부 점술 API |

#### KPI
일일 운세 수령률, 재생성율, 다음 날 재방문

### 4.3 행복 위로 (Comfort) 💌

#### 컨셉
힘든 마음을 **짧게 털어놓으면**, 직접적이고 따뜻한 위로 편지를 받는다.  
글귀(Quotes)가 “서정·작가 문체”라면, 위로는 “나에 대한 말”에 가깝다.

#### Quotes와의 차별

| | Quotes | Comfort |
|--|--------|---------|
| 입력 | 오늘의 생각 | 힘든 점/위로가 필요한 말 |
| 톤 | 문학적 명언+위로 | 1인칭에 가까운 공감 편지 |
| 분량 | 3~5줄 | 4~8줄 편지 |
| 작가 페르소나 | 있음(랜덤 작가명) | 없음(앱 페르소나 “행복담”) |

#### 타깃 유저 행동
1. 짧은 텍스트 입력 (최소 10자, 최대 500자)
2. 하트 1 소비
3. 위로 편지 수신 → 저장/다시 읽기

#### 안전
- 자해·위기 키워드 감지 시: AI 생성 대신 **도움 리소스/긴급 안내** 고정 카드
- 입력 내용 서버 로그 최소화, 보관 기간 정책 명시(제품 약관 연계)

#### MVP / Phase
| | |
|--|--|
| MVP | 입력 → AI 편지 → 히스토리 |
| Phase 2 | 감정 태그, 음성 입력 |
| Out | 실시간 상담, 의료 조언 |

#### KPI
완료율, “다시 읽기” 비율, 위기 키워드 차단 정확도(내부)

---

### 4.4 행복 꽃말 (Flowers) 🌸

#### 컨셉
하트 1개로 **오늘의 꽃과 꽃말**을 뽑아 컬렉션에 모은다. 수집·감성 카드 경험.

#### 타깃 유저 행동
1. “오늘의 꽃 뽑기”
2. 꽃 이미지 + 이름 + 꽃말 카드
3. (선택) “나에게 건네는 한 줄” AI 코멘트
4. 도감형 히스토리

#### 콘텐츠
- 카탈로그 30종 이상 시드 (ko/en 꽃말)
- 이미지: Storage `shop/flowers/` 또는 CDN
- 중복 뽑기: 허용하되 “이미 수집함” 뱃지

#### MVP / Phase
| | |
|--|--|
| MVP | 랜덤 뽑기 + 저장 + 도감 그리드 |
| Phase 2 | 희귀도, 시즌 꽃, AI 한 줄 |
| Out | 실물 꽃 배송/결제 |

#### KPI
뽑기 수, 고유 수집 수, 도감 완성도

---

### 4.5 행복 레시피 (Recipe) 🍰

#### 컨셉
기분과 시간에 맞는 **간단·따뜻한 레시피** 한 끼 제안. “요리 앱”이 아니라 **작지만 실천 가능한 행복 행동**.

#### 타깃 유저 행동
1. 필터: 기분 / 소요시간(10·20·30분) / 난이도
2. 하트 1로 추천 받기
3. 재료·단계 카드 저장

#### 콘텐츠 전략
- **MVP**: Firestore 카탈로그 큐레이션 (안전·검증된 레시피)
- **Phase 2**: Gemini로 “냉장고에 이것만 있을 때” 변형 팁(알레르기 면책 문구 필수)

#### 면책
의료·알레르기·영양 보장 아님 고지.

#### MVP / Phase
| | |
|--|--|
| MVP | 필터 + 카탈로그 추천 + 저장 |
| Phase 2 | AI 변형 팁, 즐겨찾기 |
| Out | 장보기 연동, 결제 |

#### KPI
추천→저장율, 필터 사용률

---

### 4.6 행복 여행 (Travel) ✈️

#### 컨셉
멀리 떠나지 않아도 되는 **상상 여행 / 근처 소확행 장소** 추천. 스트레스 환기용 카드.

#### 타깃 유저 행동
1. 타입 선택: `근처 산책` / `당일` / `상상 여행`
2. 하트 1로 추천
3. 장소 카드(사진·한줄 팁·분위기 태그) 저장

#### 콘텐츠
- MVP: 국내·감성 장소 카탈로그 (포토+팁)
- 위치 권한: MVP에서는 **비필수**(지역 태그 선택). Phase 2에서 근처 추천.

#### MVP / Phase
| | |
|--|--|
| MVP | 타입 칩 + 카탈로그 추천 + 히스토리 |
| Phase 2 | 위치 기반, 계절 테마, 공유 카드 |
| Out | 항공/숙소 예약 제휴(초기 비목표) |

#### KPI
타입별 선택 분포, 저장율, 공유율(Phase 2)

## 5. 우선순위 로드맵

기존 구조서 Phase와 정합:

| Phase | 범위 | 근거 |
|-------|------|------|
| **Phase A** | Fortune, Comfort | Quotes와 동일 AI+하트 파이프라인 재사용, 개발 속도↑ |
| **Phase B** | Music | `MusicProvider`·Storage 자산 재사용, 체감 가치↑ |
| **Phase C** | Flowers | 카탈로그 시드만으로 MVP 가능, 수집 재미 |
| **Phase D** | Recipe, Travel | 카탈로그 품질·저작권·면책 문구 준비 후 |

피처 플래그 예: `SHOP_FEATURE_FORTUNE=true`부터 순차 오픈.

### 예상 산출물 (카테고리당)

1. `models/*_item.dart`
2. `services/*_service.dart`
3. `screens/*_tab_screen.dart` (+ history)
4. Firestore 규칙/시드(해당 시)
5. Gemini 프롬프트(해당 시)
6. 간단 QA 체크리스트

## 6. 사용자 스토리 (요약)

1. **운세**: “아침에 하트 하나로 오늘 응원 메시지를 받고 싶다.”
2. **위로**: “힘든 말을 적으면 나를 다독이는 편지를 받고 싶다.”

4. **꽃말**: “오늘의 꽃과 꽃말을 모아 도감처럼 보고 싶다.”
5. **레시피**: “피곤할 때 10분짜리 따뜻한 레시피를 추천받고 싶다.”
6. **여행**: “못 떠날 때라도 상상 여행 카드로 숨 돌리고 싶다.”

## 7. UX 카피 가이드 (ko 예시)

| 상황 | 카피 |
|------|------|
| CTA | 하트 1개로 받기 |
| pending | 마음을 담아 준비 중이에요… |
| failed | 잠시 문제가 생겼어요. 다시 시도해 주세요. |
| insufficient | 하트가 부족해요. 미션을 완료하면 하트를 얻을 수 있어요. |
| daily limit | 오늘은 이미 받았어요. 내일 다시 만나요! |
| Music unlock | 이 곡을 내 행복송에 담을까요? |

영문은 `LocaleProvider` 분기로 동등 톤 유지.
